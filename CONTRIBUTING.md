\# Contribuindo com a LOSTTECH



\## Objetivo



Este documento define as regras para contribuições, alterações e manutenção dos projetos da LOSTTECH.



\## Antes de começar



Antes de realizar alterações:



1\. Verifique a documentação existente

2\. Entenda a estrutura do projeto

3\. Avalie o impacto da alteração

4\. Verifique possíveis dependências

5\. Confirme que nenhuma informação sensível será adicionada



\## Branches



Utilizar branches específicas para cada alteração.



Exemplos:



\- `feature/nome-da-funcionalidade`

\- `fix/nome-do-problema`

\- `hotfix/nome-do-problema`

\- `docs/nome-da-documentacao`

\- `refactor/nome-da-refatoracao`



A branch `main` deve permanecer estável.



\## Commits



Utilizar mensagens objetivas e padronizadas.



Tipos:



\- `feat:` nova funcionalidade

\- `fix:` correção

\- `docs:` documentação

\- `refactor:` refatoração

\- `test:` testes

\- `chore:` manutenção

\- `style:` formatação



Exemplo:



`feat: adicionar autenticação de usuários`



\## Código



As alterações devem priorizar:



\- Clareza

\- Organização

\- Segurança

\- Manutenibilidade

\- Reutilização

\- Simplicidade



Evitar código duplicado e alterações sem necessidade.



\## Testes



Quando aplicável, novas funcionalidades ou correções devem possuir testes adequados.



Antes do envio:



\- Executar os testes

\- Verificar erros

\- Validar funcionalidades afetadas



\## Documentação



Alterações que modificarem comportamento, instalação, configuração ou utilização devem atualizar a documentação correspondente.



\## Segurança



Nunca enviar:



\- Senhas

\- Tokens

\- API Keys

\- Chaves privadas

\- Arquivos `.env`

\- Dados sensíveis

\- Credenciais de serviços



\## Pull Requests



Alterações relevantes devem utilizar Pull Request quando aplicável.



O Pull Request deve informar:



\- O que foi alterado

\- Motivo da alteração

\- Impactos

\- Testes realizados

\- Observações importantes



\## Code Review



Quando aplicável, alterações devem ser revisadas antes de serem incorporadas à `main`.



A revisão deve considerar:



\- Funcionalidade

\- Segurança

\- Qualidade

\- Testes

\- Documentação

\- Compatibilidade



\## Responsabilidade



Toda contribuição deve respeitar os padrões técnicos, de segurança e documentação definidos pela LOSTTECH.
